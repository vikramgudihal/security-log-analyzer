About the Security Log Analyzer

Architecture, detection methodology, and internship project specifications.

🎯 Project Objective

CodeNova Task 4

In a Security Operations Center (SOC), security analysts are tasked with defending corporate infrastructure against automated credential attacks, vulnerability scans, and unauthorized intrusions.

This application acts as an automated Incident Response & Anomaly Detection Tool. It evaluates sanitized authentication logs (Linux auth.log, secure) and web server logs (Apache, Nginx Combined Log Format) completely locally, with zero external network probes or sensitive data storage.

Key Architectural Principles:

  • Strict Local Defensive Operations: No outbound API calls, no network scanning, no credential persistence.
  • Dual-Vector Ingestion: Normalizes heterogeneous SSH and Web server logs into unified LogEvent structures.
  • False-Positive Mitigation: Intelligently differentiates legitimate employee password typos during work hours from high-velocity brute-force campaigns.

🔬 The 7 Core Detection Rules

MITRE ATT&CK Aligned
  1. Repeated Failed Authentication: Groups failed logins by source IP and flags threshold breaches (1–3 LOW, 4–5 MEDIUM, >5 HIGH).
  2. Rapid Sequential Login Bursts: Identifies brute-force automation attempting ≥4 logins within a 60-second sliding window.
  3. Multiple Usernames Targeted: Detects single IPs attempting multiple accounts (credential stuffing / dictionary enumeration).
  4. Successful Login Following Failures: Flags when an IP successfully authenticates immediately after repeated failures (high-confidence compromise indicator).
  5. Off-Hours Login Activity: Detects logins outside 08:00–18:00 Mon–Fri. (Note: Never classified as CRITICAL solely due to off-hours).
  6. HTTP 401 & 403 Error Bursts: Catches rapid web access denial responses indicating endpoint enumeration.
  7. Suspicious URL Signatures: Regex-based detection for SQL Injection, Path/Directory Traversal, and Pentest scanners (Nikto, sqlmap).
